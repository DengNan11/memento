## 一、产品定义

### 1.1 一句话定义

一个具备**类人记忆机制**的个人 AI 助手——它会记住、会淡忘、会联想、会成长。

### 1.2 解决的问题

大语言模型存在上下文窗口有限的天然限制，无法实现真正的永久对话。现有方案（如直接拼接历史、简单向量检索）存在以下问题：

- **记忆无结构**：历史对话是一坨文本，无法精确管理
- **记忆无生命**：存了就不会忘，噪音随时间累积
- **记忆无关系**：条目之间孤立，缺乏联想能力
- **记忆无成长**：不会随对话加深对用户的理解

### 1.3 核心目标

| 目标 | 说明 |
|------|------|
| 有限记忆，无限交互 | 用固定的上下文预算支撑永久对话 |
| 记忆可成长 | 随对话积累，系统对用户的理解不断加深 |
| 记忆可遗忘 | 不重要的信息自然衰减淘汰，而非无限膨胀 |
| 记忆有结构 | 信息之间存在关联，而非孤立的条目列表 |

### 1.4 设计哲学

本项目的设计哲学是**模仿人类认知机制**：

| 人类认知特征 | 系统对应机制 |
|---|---|
| 记忆不是全量存储，而是选择性记住 | 条目提取 + 置信度管理 |
| 不常想起的事情会慢慢淡忘 | 置信度随时间衰减 |
| 新矛盾信息不会立刻推翻旧认知 | 冲突条目共存，自然竞争淘汰 |
| 记忆之间有联想关系 | 条目之间建立连接，形成图结构 |
| 忘记一件事会连带忘记相关的事 | 图上传播衰减 |
| 知识按领域组织 | 向量聚类分团，团内图谱存储 |

## 二、版本规划

### 2.1 全局路线图

```
V0.1  提取 → 存储 → 注入                    ← 当前版本
V0.2  + 衰减 + 淘汰 + 冲突共存竞争
V0.3  + 向量检索 + 分类标签差异化衰减
V0.4  + 向量聚类自组织
V0.5  + 图结构 + 联想检索 + 图传播衰减
V1.0  + 聚类拆分/归档区/跨聚类边/半衰期
```

### 2.2 V0.1 范围

**目标**：跑通最小闭环——对话 → 提取记忆 → 下次注入。

**做什么：**

| 功能 | 说明 |
|------|------|
| 对话循环 | 命令行交互，支持多轮对话 |
| 记忆提取 | 对话结束后，模型自动从对话中提取结构化条目 |
| 记忆存储 | 条目以 JSON 格式持久化存储 |
| 记忆注入 | 每次对话前，将已有记忆注入 system prompt |
| 简单冲突处理 | 新条目与已有条目重复时刷新，矛盾时双方打折 |
| 文件学习 | 支持从文件中读取内容并提取记忆（规划中） |

**不做什么：**

- 向量检索（V0.3）
- 聚类分组（V0.4）
- 图结构连接（V0.5）
- 置信度衰减（V0.2）
- Embedding 计算

## 三、技术架构

### 3.1 技术栈

| 组件 | 选型 |
|------|------|
| 语言 | Python 3.10+ |
| LLM | DeepSeek-V4-Flash（OpenAI 兼容 API） |
| 存储 | JSON 文件 |
| 依赖 | requests, python-dotenv |

### 3.2 文件结构

```
memento/
├── main.py              # 主程序入口，对话循环
├── memory.py            # 记忆读写与管理
├── extractor.py         # 条目提取 prompt 与解析
├── config.py            # 配置管理
├── requirements.txt     # 依赖声明
├── .env.example         # 环境变量模板
├── .gitignore
├── data/
│   └── memory.json      # 记忆存储（运行时生成，不入版本控制）
└── docs/
    ├── PRD-V0.1.md      # 本文档
    └── V0.1-design.md   # V0.1 设计文档
```

### 3.3 核心模块

#### main.py — 主程序

职责：对话主循环、LLM 调用、命令处理、记忆注入。

核心流程：

```
启动
  │
  ▼
读取 memory.json → 构建 system prompt（注入已有记忆）
  │
  ▼
用户输入 ──→ 调用 LLM ──→ 输出回复
  │                          │
  └──────── 循环 ────────────┘
  │
用户退出（/quit）或每 N 轮
  │
  ▼
调用提取器：从对话中提取条目
  │
  ▼
合并到 memory.json（处理重复/冲突）
  │
  ▼
保存
```

支持的命令：

| 命令 | 说明 |
|------|------|
| `/quit` | 退出程序，退出前触发记忆提取 |
| `/memory` | 查看当前所有记忆条目 |
| `/clear` | 清空所有记忆 |

#### memory.py — 记忆管理

职责：记忆的读写、条目合并、冲突处理、上下文拼装。

核心函数：

| 函数 | 说明 |
|------|------|
| `load_memory()` | 读取 memory.json，不存在则初始化空结构 |
| `save_memory()` | 写回 memory.json |
| `get_context_text()` | 取置信度最高的 N 条，拼成文本注入 system prompt |
| `add_entries()` | 新条目进入：检查重复/冲突，合并或新增 |

#### extractor.py — 条目提取

职责：调用 LLM 从对话文本中提取结构化记忆条目。

提取 prompt 要求模型：
- 每条信息原子化（一个条目只包含一个事实）
- 附带类别标签（category）和来源类型（source）
- 输出为 JSON 数组

## 四、数据结构

### 4.1 条目（Entry）— 记忆的最小单元

```json
{
  "id": "e_001",
  "content": "用户是研二学生",
  "category": "identity",
  "confidence": 0.8,
  "created_at": "2026-05-16",
  "last_confirmed": "2026-05-16",
  "source": "user_direct"
}
```

### 4.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识，格式 e_XXX，自动生成 |
| content | string | 记忆内容，一句话，原子化 |
| category | enum | 条目类别 |
| confidence | float | 置信度，0.0-1.0 |
| created_at | date | 创建时间 |
| last_confirmed | date | 最后一次被确认的时间 |
| source | enum | 来源类型 |

### 4.3 条目类别

| 类别 | 描述 | 示例 |
|------|------|------|
| identity | 用户身份信息 | 职业、学历、技术栈 |
| preference | 用户偏好 | 编码风格、沟通方式、工具偏好 |
| opinion | 用户观点/认知 | 对某项技术的看法 |
| project | 当前项目状态 | 正在做的项目、遇到的问题 |
| behavior | 行为模式 | 什么时候活跃、习惯怎么工作 |
| relationship | 提到的人/团队 | 同事、导师、协作关系 |
| event | 具体事件 | 设计了一次实验、做了一次汇报 |

### 4.4 来源类型

| 来源 | 初始置信度 | 说明 |
|------|-----------|------|
| user_direct | 0.8 | 用户直接陈述的事实 |
| preference | 0.6 | 用户表达的偏好/观点 |
| inferred | 0.4 | 模型推断的结论 |

### 4.5 memory.json 整体结构

```json
{
  "entries": [
    { "id": "e_001", "content": "...", "category": "...", ... },
    { "id": "e_002", "content": "...", "category": "...", ... }
  ],
  "meta": {
    "total_conversations": 12,
    "last_updated": "2026-05-17"
  }
}
```

## 五、核心机制详解

### 5.1 记忆提取

**触发时机：**
- 用户输入 `/quit` 退出时
- 每 N 轮对话自动触发（默认 N=10）

**提取流程：**
1. 将对话内容格式化为纯文本
2. 调用 LLM，要求输出结构化 JSON 数组
3. 解析响应，验证格式
4. 逐条合并到记忆库

### 5.2 记忆注入

每次对话启动时：
1. 按 confidence 降序排列所有条目
2. 取前 20 条拼成文本
3. 注入 system prompt，模型据此了解用户

System prompt 模板：

```
你是一个个人助手。以下是你对用户的了解：

{记忆条目列表}

请基于这些了解来辅助用户。不要主动暴露你知道这些信息，除非自然地需要引用。
回复简洁、自然，像一个了解用户的朋友。
```

### 5.3 冲突处理（V0.1 简化版）

新条目进入时：

```
遍历已有条目，计算字符串相似度
if 相似度 > 0.6:
    if 内容矛盾:
        旧条目 confidence × 0.7
        新条目 confidence = 0.5
        两条都保留
    else:
        视为重复，刷新旧条目的 last_confirmed
        旧条目 confidence += 0.05（上限 1.0）
else:
    作为全新条目加入
```

矛盾检测方式（V0.1 简化）：检查关键词如"不"、"不是"、"换了"、"改了"等否定/变化词是否在新旧条目中不对称出现。

## 七、后续版本设计预览

### V0.2 — 置信度衰减与淘汰

- 所有条目在每次对话后都受影响（不只是被提到的）
- 被提及的条目置信度上升，未被提及的微弱衰减
- 置信度低于阈值的条目移入归档区
- 冲突条目共存竞争，自然淘汰而非即时推翻

### V0.3 — 向量检索

- 每条记忆计算 embedding
- 用户输入计算向量，找到最相关的 N 条注入
- 不同类别使用不同衰减速率

### V0.4 — 向量聚类

- 条目按 embedding 相似度自动聚类
- 两级检索：先找聚类，再在聚类内找条目
- 聚类自动拆分/合并

### V0.5 — 图结构

- 条目间建立连接（基于共现）
- 检索时沿边遍历关联条目（联想机制）
- 图传播衰减：关联条目一起衰减

### V1.0 — 完整记忆系统

- 聚类内图谱 + 规模上限 + 自动拆分
- 归档区与记忆恢复
- 跨聚类边连接
- 半衰期差异化管理
- 完整的生命周期：新增 → 成长 → 衰减 → 淘汰 → 归档 → 恢复

## 八、关键设计决策记录

| 决策点 | 选择 | 原因 |
|--------|------|------|
| 记忆粒度 | 原子化条目，非整段摘要 | 便于独立更新、独立淘汰、独立检索 |
| 存储结构 | JSON 文件（V0.1） | 简单直接，后续版本升级为向量+图谱 |
| 冲突处理 | 慢性淡忘，非即时推翻 | 更符合人类认知习惯，避免错误删除 |
| 初始置信度 | 按来源分三档 | 用户直接说的比模型推断的更可信 |
| 提取时机 | 退出时 + 每 N 轮 | 避免频繁调用 API，同时保证记忆及时更新 |
| 注入方式 | 按 confidence 排序取 top N | 简单有效，后续改为向量检索 |
