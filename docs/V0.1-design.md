# Memento V0.1 设计文档

> 版本：V0.1  
> 日期：2026-05-16  
> 状态：开发中

## 一、项目愿景

构建一个具备类人记忆机制的个人助手系统。记忆不是静态的数据库，而是一个活的、会成长、会遗忘的有机体。

## 二、V0.1 目标

**跑通最小闭环：对话 → 提取记忆 → 下次注入。**

验证核心假设：模型能从对话中提取有价值的信息，并在后续对话中有效利用这些信息。

## 三、V0.1 范围

### 做什么

| 功能 | 说明 |
|------|------|
| 对话循环 | 命令行交互，支持多轮对话 |
| 记忆提取 | 对话结束后，模型自动从对话中提取结构化条目 |
| 记忆存储 | 条目以 JSON 格式持久化存储 |
| 记忆注入 | 每次对话前，将已有记忆注入 system prompt |
| 简单冲突处理 | 新条目与已有条目重复时刷新，矛盾时双方打折 |

### 不做什么

- 向量检索（V0.3）
- 聚类分组（V0.4）
- 图结构连接（V0.5）
- 置信度衰减（V0.2）
- Embedding 计算

## 四、技术方案

### 技术栈

- **语言**：Python 3.10+
- **LLM**：DeepSeek-V4-Flash（OpenAI 兼容 API）
- **存储**：JSON 文件
- **依赖**：requests, python-dotenv

### 数据结构

#### memory.json

```json
{
  "entries": [
    {
      "id": "e_001",
      "content": "用户是Go开发者，3年经验",
      "category": "identity",
      "confidence": 0.8,
      "created_at": "2026-05-16",
      "last_confirmed": "2026-05-16",
      "source": "user_direct"
    }
  ],
  "meta": {
    "total_conversations": 12,
    "last_updated": "2026-05-16"
  }
}
```

#### 条目字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识，格式 e_XXX |
| content | string | 记忆内容，一句话，原子化 |
| category | enum | identity / preference / opinion / project / behavior / relationship / event |
| confidence | float | 置信度，0.0-1.0 |
| created_at | date | 创建时间 |
| last_confirmed | date | 最后一次被确认的时间 |
| source | enum | user_direct / inferred / preference |

### 核心流程

```
启动
  │
  ▼
读取 memory.json → 构建 system prompt（注入已有记忆）
  │
  ▼
用户输入 ──→ 调用 LLM ──→ 输出回复
  │                          │
  └──────── 循环 ────────────┘
  │
用户退出（/quit）
  │
  ▼
调用提取器：从对话中提取条目
  │
  ▼
合并到 memory.json（处理重复/冲突）
  │
  ▼
保存，退出
```

### 提取 Prompt 设计

提取器使用独立的 prompt 调用模型，要求模型从对话中提取结构化信息：

- 每条信息原子化（一个条目只包含一个事实）
- 附带类别标签和来源类型
- 输出为 JSON 数组

### 冲突处理策略（V0.1 简化版）

```
新条目进入时：
  遍历已有条目，计算字符串相似度
  if 相似度 > 0.8:
    if 内容矛盾（模型判断）:
      旧条目 confidence × 0.7
      新条目 confidence = 0.5
      两条都保留
    else:
      视为重复，刷新旧条目的 last_confirmed
      旧条目 confidence += 0.05（上限 1.0）
  else:
    作为全新条目加入
```
